À lire avant de commencer Trois points conditionnent la réussite du déploiement :
  1. La connexion se fait par mot de passe + code à usage unique envoyé par e-mail : sans serveur SMTP fonctionnel, personne ne peut se connecter en production.
  2. Le paquet yajra/laravel-oci8 exige l'extension PHP oci8 : composer install échoue si elle est absente (deux solutions sont données en 4.1).
  3. Le frontend est compilé : son adresse d'API est figée au moment du build. Un .env de développement laissé en place enverrait les appels vers localhost.

1.Comprendre le projet avant de déployer

Le dépôt contient deux applications distinctes, qui doivent être déployées ensemble mais se configurent séparément.

1.1 Deux applications, une seule adresse

DossierRôleTechnologies
dgi-backend/ API REST, authentification, règles de détection, PDF, imports Laravel 13 · PHP 8.3+ · Sanctum (jetons) · DomPDF · oci8 (sources Oracle)
dgi-frontend/ Interface web (tableau de bord, anomalies, administration, comparatif) React 18 · TypeScript · Vite 5 · Tailwind CSS 3 · axios

En production, le navigateur ne parle qu'à une seule origine (par exemple https://dgi.exemple.mg) : nginx sert les fichiers statiques du frontend et transmet /api/… à Laravel. C'est ce qui évite toute configuration CORS et tout problème de cookie.

Chemin d'une requête

Navigateur │ GET https://dgi.exemple.mg/admin/centres ├─► nginx ──► /var/www/dgi/dgi-frontend/dist/index.html (SPA React) │ │ GET https://dgi.exemple.mg/api/statistiques/centres ├─► nginx ──► PHP-FPM ──► dgi-backend/public/index.php (Laravel) │ │ │ ├─► PostgreSQL (base applicative : users, alertes, centres…) │ └─► Oracle (bases sources, LECTURE SEULE, facultatif) └─◄ JSON

1.2 Ce que le dépôt ne contient pas

Ces éléments sont volontairement ignorés par Git et doivent être recréés sur le serveur :

  • dgi-backend/.env — la configuration et les secrets ;
  • dgi-backend/vendor/ — dépendances PHP, recréées par composer install ;
  • dgi-frontend/node_modules/ — dépendances JavaScript, recréées par npm ci ;
  • dgi-frontend/dist/ — le build de production, recréé par npm run build ;
  • les journaux, caches et fichiers uploadés.

1.3 Deux bases de données à ne pas confondre

BaseRôleConfiguration
Base applicative Lecture / écriture DB_* — PostgreSQL recommandé. Contient utilisateurs, centres, alertes, historiques, règles.
Bases sources Lecture seule SOURCE_DB_* / DGI_SOURCE_CONNECTION_* — Oracle en production, PostgreSQL en test. Servent à importer contribuables, déclarations et centres officiels.
Sans bases sources, l'application démarre quand même Le socle (connexion, utilisateurs, centres saisis à la main) fonctionne sans Oracle. Les sources ne deviennent nécessaires que pour l'import massif et les règles de recoupement.

2.3 Vérifier la version et les extensions PHP

php -v
php -m | grep -E 'pdo_pgsql|mbstring|dom|curl|zip|gd|bcmath|openssl|tokenizer'
Version minimale : 8.3.36 (ou 8.4.27) Le 21/10/2026, deux exécutions de code à distance critiques, non authentifiées, ont été corrigées en 8.5.12, 8.4.27, 8.3.36 et 8.2.35 : CVE-2026-109618 et CVE-2026-109619 (« php2shell », CVSS 9.2). Elles figurent au catalogue KEV de la CISA depuis le 26/10/2026, donc avec exploitation active constatée. Toutes les interfaces web sont concernées (PHP-FPM, mod_php, php-cgi, FrankenPHP, LiteSpeed) ; mod_php est le cas le plus exposé, car l'état global y persiste dans le processus Apache.

php -v doit afficher 8.3.36 au minimum — jamais 8.3.6, la version livrée par les dépôts Ubuntu 24.04. En mesure d'attente uniquement : session.upload_progress.enabled=0.

Les extensions suivantes doivent apparaître (Laravel + DomPDF + PostgreSQL) :

4.Configurer et initialiser le backend Laravel

Toutes les commandes de cette partie s'exécutent dans /var/www/dgi/dgi-backend.

4.1 Installer les dépendances PHP

cd /var/www/dgi/dgi-backend
composer install --no-dev --optimize-autoloader
Échec attendu sans Oracle : ext-oci8 yajra/laravel-oci8 déclare ext-oci8 comme dépendance. Sur un serveur sans Oracle Instant Client, Composer s'arrête avec « Your requirements could not be resolved… ext-oci8 ». Deux issues :
  • Les sources Oracle sont utilisées → installez le client et l'extension (annexe C), puis relancez la commande ;
  • Oracle n'est pas utilisé pour l'instant → ignorez la plateforme : composer install --no-dev --ignore-platform-req=ext-oci8. Le reste de l'application fonctionne ; seul le pilote oracle échouera si vous le configurez plus tard.

Contrôle final :

php artisan --version
composer check-platform-reqs | tail -n 5

VariablePourquoi elle compte
APP_URLBase des URL générées par Laravel (liens, PDF, redirections).

4.3 Créer le schéma et les données de départ

php artisan migrate --force
php artisan db:seed --class=FonctionSeeder --force

FonctionSeeder crée les quatre fonctions de base (Super administrateur, Responsable central, Chef de centre, Agent). Les rôles sont portés par les fonctions, pas directement par les utilisateurs.

Ne lancez pas php artisan db:seed sans classe Le seeder par défaut du squelette Laravel crée un « Test User » incompatible avec le schéma réel (la colonne name n'existe pas). Utilisez uniquement les seeders nommés, à commencer par FonctionSeeder.

Créer le premier super administrateur

php artisan dgi:make-superadmin admin@dgi.gov.mg --nom="Administrateur DGI"

La commande demande le mot de passe (8 caractères minimum) de façon interactive. Elle crée le compte s'il n'existe pas, ou promeut un compte existant. C'est le seul point d'entrée possible : toute la gestion des utilisateurs en dépend.

4.4 Importer les centres (facultatif à ce stade)

Après migration, la base ne contient que le service central SSIF. Deux méthodes :

  • Depuis l'interface : Administration → Centres → « + Ajouter un centre » ;
  • Depuis la base source, si elle est configurée (annexe C) : php artisan dgi:importer-centres.

4.5 Droits sur les fichiers

sudo chown -R www-data:www-data storage bootstrap/cache
sudo find storage bootstrap/cache -type d -exec chmod 775 {} \;
sudo find storage bootstrap/cache -type f -exec chmod 664 {} \;
sudo chown $USER:www-data .env
sudo chmod 640 .env
Pourquoi ces droits ? Laravel écrit dans storage/ (journaux, sessions, vues compilées, PDF temporaires) et dans bootstrap/cache/. Le reste du code doit rester en lecture seule pour le serveur web.

4.6 Figer la configuration

sudo -u www-data php artisan optimize

optimize met en cache la configuration, les routes, les événements et les vues. Exécutez-le en tant que www-data : sinon, les fichiers de cache appartiennent à root et l'application ne peut plus les mettre à jour.

Après toute modification du .env : sudo -u www-data php artisan optimize:clear puis optimize à nouveau.

5.Construire le frontend React

Le frontend est une application statique : une fois compilée, aucun serveur Node n'est nécessaire.

5.1 Installer les dépendances

cd /var/www/dgi/dgi-frontend
npm ci

npm ci installe exactement les versions du package-lock.json. Le build lance tsc --noEmit : les dépendances de développement (TypeScript, Vite) sont donc nécessaires. Si votre environnement force NODE_ENV=production, utilisez npm ci --include=dev.

5.2 Adresse de l'API : le piège du .env

L'URL de l'API est lue au moment du build via VITE_API_URL. En l'absence de cette variable, l'application appelle /api sur sa propre origine — c'est le comportement souhaité en production.

Un .env de développement peut casser la production Si le fichier dgi-frontend/.env contient VITE_API_URL=http://127.0.0.1:8000/api (valeur typique du poste de développement), le build de production appellera localhost depuis le navigateur de l'utilisateur. Créez donc un .env.production, prioritaire sur .env : 
printf 'VITE_API_URL=/api\n' > .env.production

5.3 Compiler

cd /var/www/dgi/dgi-frontend
npm run build
ls -la dist
head -c 400 dist/index.html

Le build doit produire :

dist/ ├── index.html ├── theme-init.js ├── favicon.svg ├── logo-dgi.png ├── logo-mef.png ├── icons.svg ├── efehy-auth.jpg └── assets/ ├── index-XXXXXXXX.js (bundle principal) ├── ComparatifCentresPage-XXXXXXXX.js (page chargée à la demande) └── index-XXXXXXXX.css

6.Mettre en place nginx, PHP-FPM et HTTPS

nginx sert le build React et transmet uniquement /api/… à Laravel. Le code PHP reste hors de la racine web.

6.1 Le virtual host

Créez /etc/nginx/sites-available/dgi :

server {
    listen 80;
    listen [::]:80;
    server_name dgi.exemple.mg;

    # Le frontend compilé
    root /var/www/dgi/dgi-frontend/dist;
    index index.html;
    charset utf-8;

    # Téléversements et pièces jointes
    client_max_body_size 32m;

    # --- API Laravel ------------------------------------------------
    location ^~ /api/ {
        include fastcgi_params;
        fastcgi_pass unix:/run/php/php8.3-fpm.sock;
        fastcgi_param SCRIPT_FILENAME /var/www/dgi/dgi-backend/public/index.php;
        fastcgi_param SCRIPT_NAME /index.php;
        fastcgi_param DOCUMENT_ROOT /var/www/dgi/dgi-backend/public;

        # Un client ne doit jamais pouvoir imposer ces valeurs :
        # sans elles, un X-Forwarded-Host forgé est cru par Laravel.
        fastcgi_param HTTP_X_FORWARDED_HOST  $host;
        fastcgi_param HTTP_X_FORWARDED_PROTO $scheme;
        fastcgi_param HTTP_X_FORWARDED_FOR   $remote_addr;
        fastcgi_param HTTP_X_FORWARDED_PORT  $server_port;
    }

    # --- Sonde de santé Laravel (/up) --------------------------------
    location = /up {
        include fastcgi_params;
        fastcgi_pass unix:/run/php/php8.3-fpm.sock;
        fastcgi_param SCRIPT_FILENAME /var/www/dgi/dgi-backend/public/index.php;
        fastcgi_param SCRIPT_NAME /index.php;
        fastcgi_param DOCUMENT_ROOT /var/www/dgi/dgi-backend/public;
    }

    # --- Fichiers du build : cache long ------------------------------
    location /assets/ {
        expires 1y;
        try_files $uri =404;
    }

    # --- Routes React : tout retombe sur index.html ------------------
    location / {
        try_files $uri $uri/ /index.html;
    }

    # --- En-têtes de sécurité (voir docs/securite-deploiement.md) ----
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-Frame-Options "DENY" always;
    add_header Referrer-Policy "no-referrer" always;
    add_header Permissions-Policy "camera=(), microphone=(), geolocation=()" always;
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
    add_header Content-Security-Policy "default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com; font-src https://fonts.gstatic.com; img-src 'self' data:; connect-src 'self'; frame-src 'self'; object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'" always;
}
Pourquoi ^~ /api/ ? Ce préfixe empêche try_files de servir index.html à la place de l'API. SCRIPT_FILENAME pointe vers dgi-backend/public/index.php : le code Laravel n'a pas besoin d'être dans la racine web.

Variante : vous pouvez aussi copier dist/* dans dgi-backend/public/ et utiliser une seule racine. La méthode ci-dessus garde les deux projets séparés et n'écrase jamais index.php.
Piège des en-têtes nginx Dès qu'un bloc location déclare son propre add_header, il n'hérite plus de ceux du bloc server. C'est pourquoi /assets/ n'utilise que expires : les en-têtes de sécurité restent ainsi appliqués partout. Contrôlez le résultat avec curl -I (partie 8).
Les en-têtes X-Forwarded-* doivent être écrasés TRUSTED_PROXIES=127.0.0.1 est indispensable pour que les limitations par IP voient la vraie adresse du client. Mais en FastCGI, nginx transmet tous les en-têtes du navigateur, y compris ceux qu'un attaquant forge. Comme la requête arrive bien de 127.0.0.1, Laravel les croit : un X-Forwarded-Host: site-pirate.mg suffit à détourner les URL générées (liens d'e-mail, redirections). C'est le vecteur de CVE-2026-123339. Les quatre lignes fastcgi_param HTTP_X_FORWARDED_* ci-dessus écrasent ces valeurs avec les vraies : ne les supprimez pas, et n'ajoutez jamais private_ranges dans TRUSTED_PROXIES (CVE-2026-121619).

6.2 Activer le site et recharger nginx

sudo ln -s /etc/nginx/sites-available/dgi /etc/nginx/sites-enabled/dgi
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t
sudo systemctl reload nginx
sudo systemctl enable nginx

6.3 Limites PHP-FPM (imports)

Éditez /etc/php/8.3/fpm/php.ini et alignez les valeurs sur nginx :

upload_max_filesize = 32M
post_max_size = 32M
memory_limit = 256M
max_execution_time = 120
sudo systemctl restart php8.3-fpm
sudo systemctl status php8.3-fpm --no-pager
Le socket FPM Vérifiez son nom exact : ls /run/php/. Sur PHP 8.4, ce sera php8.4-fpm.sock — la valeur doit correspondre à celle du virtual host.

6.4 HTTPS avec Let's Encrypt

sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d dgi.exemple.mg
sudo systemctl status certbot.timer --no-pager

Certbot réécrit le virtual host (redirection HTTP → HTTPS et certificat). Le renouvellement est automatique. Si le serveur n'a pas d'accès Internet entrant, installez un certificat de l'autorité interne et adaptez manuellement les directives ssl_*.

Après le passage en HTTPS Mettez à jour APP_URL, FRONTEND_URL et CORS_ALLOWED_ORIGINS avec https://, puis relancez sudo -u www-data php artisan optimize. Un mélange HTTP/HTTPS provoque des erreurs de contenu mixte et des appels API bloqués.

7.Exploitation courante

Trois mécanismes doivent tourner après la mise en ligne : le planificateur, la purge des jetons et les sauvegardes.

7.1 Planificateur Laravel (obligatoire)

Trois tâches sont planifiées par l'application :

  • Purge quotidienne des jetons Sanctum expirés — sans elle, la table personal_access_tokens grossit indéfiniment ;
  • Rappel du code d'activation, une heure avant son expiration ;
  • Clôture des demandes dont le code d'activation a expiré sans être saisi.
sudo crontab -u www-data -e

Ajoutez cette ligne :

* * * * * cd /var/www/dgi/dgi-backend && /usr/bin/php artisan schedule:run >> /dev/null 2>&1

Vérification :

sudo -u www-data php /var/www/dgi/dgi-backend/artisan schedule:list
Après approbation d'un compte : 24 heures Le code envoyé à l'agent est valable 24 heures. Une heure avant l'échéance, il reçoit un rappel par e-mail. Passé le délai, la demande est automatiquement clôturée : le code devient inutilisable, le matricule est libéré et l'agent doit déposer une nouvelle demande d'inscription. Les deux tâches correspondantes tournent toutes les cinq minutes — sans crontab, ce rappel et cette clôture n'ont jamais lieu.

10.Dépannage

Les incidents ci-dessous couvrent la quasi-totalité des échecs constatés lors d'un premier déploiement.

10.1 Erreurs HTTP

SymptômeCause probableCorrection
502 Bad Gateway PHP-FPM arrêté ou socket erroné. ls /run/php/, corriger fastcgi_pass, systemctl restart php8.3-fpm.
500 sur /api/… Permissions, clé absente, erreur SQL. tail storage/logs/laravel-*.log, vérifier storage et bootstrap/cache.
404 sur /admin/... au rechargement try_files absent. Ajouter try_files $uri $uri/ /index.html; dans location /.
Page blanche, assets en 404 Build absent ou root mal pointé. Relancer npm run build, vérifier /assets/*.js et les droits de lecture.
413 Request Entity Too Large Pièce jointe trop volumineuse. client_max_body_size (nginx) + upload_max_filesize/post_max_size (PHP).
Mixed content / requêtes bloquées URL en http:// dans la configuration ou le build. Tout passer en https://, reconstruire le front, artisan optimize.

10.2 Connexion et e-mails

SymptômeCause probableCorrection
« Identifiants incorrects » avec le bon mot de passe Compte incomplet (mot de passe jamais défini) ou désactivé. Recréer via dgi:make-superadmin ; vérifier desactive_le.
Code OTP jamais reçu SMTP mal configuré, port bloqué, expéditeur non autorisé. Tester MAIL_*, lire le journal (échec explicite), essayer 587 puis 465.
Liens d'e-mail vers localhost:5173 FRONTEND_URL non défini et configuration en cache. Définir FRONTEND_URL puis optimize:clear + optimize.
401 après quelques heures Jeton expiré. Comportement normal (480 min). Ajuster SANCTUM_EXPIRATION si nécessaire.
Erreur CORS Origine du front absente ou différente (slash, port, http/https). Même origine recommandée ; sinon CORS_ALLOWED_ORIGINS exacte, sans slash final.
429 « Trop de tentatives » Limitation par IP ou par compte après plusieurs échecs. Attendre 15 minutes ; vérifier TRUSTED_PROXIES pour une IP réelle.

SymptômeCause probableCorrection

11.Durcissement et bonnes pratiques

L'application manipule des données fiscales nominatives : le minimum ci-dessous n'est pas optionnel.

  • APP_ENV=production et APP_DEBUG=false ; jamais de trace d'erreur visible.
  • .env en 640, propriétaire du compte de déploiement, groupe www-data ; absent du dépôt.
  • Base PostgreSQL accessible uniquement en local (listen_addresses = 'localhost').
  • Compte Oracle source en lecture seule ; ne jamais réutiliser un compte applicatif.
  • Pare-feu : seuls 22, 80 et 443 exposés.
  • HTTPS obligatoire, HSTS actif, redirection HTTP → HTTPS.
  • En-têtes X-Frame-Options, nosniff, CSP et Referrer-Policy vérifiés par curl -I.
  • Sauvegardes chiffrées, testées par une restauration réelle au moins une fois.
  • Mots de passe uniques par personne ; aucun compte partagé ; comptes partants désactivés (fonction prévue dans l'application).
  • Journaux conservés 30 jours minimum et surveillés (échecs SMTP, 500, pics de 429).
  • fail2ban conseillé sur SSH et sur les erreurs 401/429 répétées de nginx.
  • Mises à jour système mensuelles (unattended-upgrades pour la sécurité).
  • PHP en 8.3.36 minimum (8.4.27 conseillé) : vérifié à chaque déploiement.
  • composer audit sans avis avant chaque mise en ligne.
  • En-têtes X-Forwarded-* écrasés dans nginx ; TRUSTED_PROXIES en liste explicite d'adresses.
Ne jamais exposer dgi-backend/.env, dgi-backend/storage/, dgi-backend/vendor/ ni le port 5432. La configuration nginx de la partie 6 ne sert que dist/ et public/index.php : conservez cette séparation.

E.3 Points de vigilance en développement

  • Le code OTP est renvoyé dans la réponse API uniquement si APP_DEBUG=true et APP_ENV=local. En production, il n'apparaît jamais.
  • Avec MAIL_MAILER=log, le code se lit dans storage/logs/laravel.log.
  • Les comptes de test cités dans la documentation interne (super admin, chef de centre) ne sont pas versionnés : ils se recréent avec les commandes ci-dessus.
  • Ne jamais copier un .env de développement sur le serveur.
