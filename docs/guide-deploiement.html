GUIDE PRATIQUE · WINDOWS 10/11

Installer DGI E-Fehy sur un autre PC

Récupérer le code sur GitHub, préparer les bases, lancer l'application et créer le premier compte administrateur.

Ce guide installe l'application pour un usage local ou de démonstration sur un PC Windows. Il ne configure pas un serveur public de production. Les commandes sont à exécuter dans PowerShell, sauf lorsqu'une étape demande explicitement un autre outil.

À savoir : le projet contient deux composants (API Laravel/PHP et interface React) et utilise PostgreSQL pour ses données applicatives. La connexion aux bases Oracle de la DGI est facultative pour afficher et tester le socle de l'application ; elle est nécessaire seulement pour importer des données depuis Oracle.

1. Préparer le PC

Prévoir Windows 10/11 64 bits, une connexion Internet, les droits d'installation et environ 10 Go d'espace libre. Installer les outils suivants depuis leurs sites officiels :

  • Git for Windows ;
  • Laravel Herd pour Windows — fournit PHP et Composer ; choisir PHP 8.3 ou plus récent ;
  • Node.js LTS 22 — fournit npm ;
  • PostgreSQL 16 ou plus récent — conserver le port par défaut 5432 et noter le mot de passe du compte postgres.

Après installation, fermer puis rouvrir PowerShell. Vérifier les outils :

git --version
php -v
composer --version
node --version
npm --version

PHP doit être en version 8.3 ou supérieure. Si php ou composer n'est pas reconnu, vérifier l'installation et le PATH de Herd, puis rouvrir le terminal.

2. Créer la base PostgreSQL

  1. Ouvrir SQL Shell (psql) depuis le menu Démarrer.
  2. Garder les valeurs proposées pour serveur (localhost), base (postgres) et port (5432), saisir l'utilisateur postgres, puis son mot de passe défini pendant l'installation.
  3. Dans l'invite SQL, créer un compte réservé à l'application et sa base. Remplacer le mot de passe d'exemple par un mot de passe choisi pour ce PC :
CREATE ROLE dgi_app LOGIN PASSWORD 'RemplacerParUnMotDePasseFort';
CREATE DATABASE dgi_app OWNER dgi_app;

Quitter SQL Shell avec \q. Noter le mot de passe de dgi_app : il sera ajouté au fichier de configuration.

3. Télécharger le code depuis GitHub

Dans PowerShell, créer un dossier de travail et cloner le dépôt officiel :

New-Item -ItemType Directory -Force C:\projets | Out-Null
Set-Location C:\projets
git clone https://github.com/hagasantatra4336/Projet-hg.git
Set-Location C:\projets\Projet-hg

Si GitHub indique que le dépôt est privé ou refuse l'accès, demander au propriétaire du dépôt de donner accès au compte GitHub du nouvel utilisateur. Ne mettez jamais un mot de passe ou un jeton GitHub dans l'URL de clonage.

Le code est alors dans C:\projets\Projet-hg. En cas de mise à jour ultérieure, lancer git pull depuis ce dossier après avoir sauvegardé les données locales.

4. Configurer le backend Laravel

Préparer le fichier d'environnement à partir du modèle fourni par le projet :

Set-Location C:\projets\Projet-hg\dgi-backend
Copy-Item .env.example .env
notepad .env

Dans le Bloc-notes, conserver les autres réglages du modèle et remplacer au minimum les valeurs suivantes. Le mot de passe doit être celui créé à l'étape 2 :

APP_ENV=local
APP_DEBUG=true
APP_URL=http://127.0.0.1:8000
FRONTEND_URL=http://localhost:5173
CORS_ALLOWED_ORIGINS=http://localhost:5173

DB_CONNECTION=pgsql
DB_HOST=127.0.0.1
DB_PORT=5432
DB_DATABASE=dgi_app
DB_USERNAME=dgi_app
DB_PASSWORD="RemplacerParUnMotDePasseFort"

MAIL_MAILER=log

Enregistrer puis fermer le Bloc-notes. MAIL_MAILER=log est adapté à un essai local : les courriels (notamment les codes OTP) sont écrits dans les journaux Laravel, pas envoyés. Pour un usage réel, configurer un fournisseur SMTP ; ne pas réutiliser ces réglages locaux sur un serveur.

5. Installer les dépendances et initialiser l'application

Toujours dans PowerShell, depuis dgi-backend, installer les bibliothèques PHP. Le pilote Oracle est facultatif tant que l'import Oracle n'est pas utilisé ; l'option ci-dessous permet l'installation sans OCI8 :

composer install --no-interaction --prefer-dist --ignore-platform-req=ext-oci8

Générer la clé de l'application, vider une éventuelle configuration en cache et créer les tables :

php artisan key:generate
php artisan config:clear
php artisan migrate

Créer les fonctions et rôles de base, puis le compte administrateur. Remplacer l'adresse et le nom ; la commande demandera un mot de passe sans l'afficher :

php artisan db:seed --class=FonctionSeeder
php artisan dgi:make-superadmin administrateur@example.com --nom="Administrateur"
Ne pas exécuter php artisan db:seed sans préciser la classe sur une installation destinée à conserver des données : le seeder général contient des données de démonstration.

6. Installer les dépendances du frontend

Dans PowerShell :

Set-Location C:\projets\Projet-hg\dgi-frontend
npm ci

npm ci utilise les versions verrouillées dans le dépôt. Aucun fichier .env du frontend n'est nécessaire pour l'adresse locale par défaut : Vite transmet les appels /api au backend local.

7. Démarrer et ouvrir l'application

Garder deux fenêtres PowerShell ouvertes. Dans la première, démarrer l'API :

Set-Location C:\projets\Projet-hg\dgi-backend
php artisan serve --host=127.0.0.1 --port=8000

Dans la deuxième, démarrer l'interface :

Set-Location C:\projets\Projet-hg\dgi-frontend
npm run dev

Ouvrir http://localhost:5173 dans le navigateur et se connecter avec l'adresse et le mot de passe du superadministrateur créés à l'étape 5. Garder les deux fenêtres ouvertes pendant l'utilisation ; Ctrl+C arrête chaque service.

Ces serveurs sont des serveurs de développement, destinés à un usage local. Ne les exposez pas directement à Internet et ne les utilisez pas comme déploiement de production.

Tester les liens des courriels depuis un téléphone (même Wi-Fi)

Sur le PC qui héberge l'application, lancer ipconfig et relever l'adresse IPv4 de sa carte Wi-Fi (par exemple 192.168.1.25). Le téléphone et le PC doivent être connectés au même réseau Wi-Fi. Sur le téléphone, ouvrir d'abord l'application avec cette adresse, jamais avec localhost.

Dans dgi-backend\.env, remplacer l'adresse locale par l'IPv4 réelle du PC :

FRONTEND_URL=http://192.168.1.25:5173
CORS_ALLOWED_ORIGINS=http://192.168.1.25:5173

Remplacer 192.168.1.25 par l'adresse trouvée sur le PC, puis exécuter php artisan config:clear depuis dgi-backend et redémarrer le serveur Laravel. Ouvrir ensuite http://192.168.1.25:5173 sur le téléphone. Si la connexion est toujours refusée, autoriser le port 5173 dans le pare-feu Windows pour le réseau privé, et vérifier que les deux appareils sont sur le même Wi-Fi. Renvoyer le courriel après le changement : un lien déjà reçu gardera son ancienne adresse localhost.

Cette méthode est réservée à un test sur un réseau local de confiance. Pour des utilisateurs hors de ce réseau, utilisez un nom de domaine accessible en HTTPS et un déploiement serveur ; ne publiez pas les serveurs de développement.

8. Vérifier l'installation et dépanner

  • Erreur de connexion PostgreSQL : vérifier que le service PostgreSQL est démarré, que le port est 5432 et que le nom de base, l'utilisateur et le mot de passe du fichier .env correspondent à l'étape 2. Après une modification, exécuter php artisan config:clear.
  • Port 8000 ou 5173 déjà utilisé : fermer l'application qui l'occupe ou choisir un autre port, puis adapter la cible proxy dans dgi-frontend/vite.config.ts si le port backend change.
  • Échec Composer mentionnant OCI8 : relancer la commande de l'étape 5 avec --ignore-platform-req=ext-oci8. Ne pas ignorer d'autres extensions PHP manquantes ; elles doivent être installées/activées dans Herd.
  • Erreur de dépendances PHP : vérifier php -v, l'accès Internet, puis composer install. Les extensions PostgreSQL, notamment pdo_pgsql, doivent être activées pour le PHP utilisé en ligne de commande.
  • Codes OTP en essai : consulter dgi-backend\storage\logs\laravel.log. L'envoi réel nécessite un compte SMTP configuré dans dgi-backend\.env.

9. Activer les imports Oracle (facultatif)

Sans source Oracle, il est possible de démarrer et d'utiliser le compte administrateur, mais les imports de contribuables, déclarations, centres Oracle et données de recoupement ne fonctionneront pas. Pour ces imports, il faut un accès à un serveur Oracle (sur le réseau ou local) et installer le client Oracle Instant Client ainsi que l'extension PHP OCI8.

  • Installer OCI8 sur Windows : dgi-backend/docs/installation-oracle-oci8-windows.md.
  • Créer un serveur Oracle de démonstration local : dgi-backend/docs/serveur-oracle-local-windows.md.

Après configuration Oracle, compléter les variables SOURCE_DB_* dans dgi-backend\.env, exécuter php artisan config:clear, puis tester avec php artisan dgi:importer-source --tester. Utiliser uniquement des identifiants Oracle autorisés et en lecture seule. Les scripts de création de données de démonstration ne doivent jamais être exécutés sur une base de production.

10. Sécurité et suite

  • Ne jamais envoyer le fichier dgi-backend\.env à GitHub : il contient la clé et les mots de passe locaux.
  • Pour déplacer l'application vers un serveur accessible à plusieurs personnes, suivre le guide dédié au serveur Ubuntu : docs/guide-deploiement-ubuntu.html ou docs/deploiement-serveur-physique.md. Un serveur de production nécessite notamment HTTPS, des sauvegardes, un SMTP opérationnel et une configuration adaptée.
  • Conserver séparément le dépôt de code et les données de la base PostgreSQL ; le clonage GitHub ne sauvegarde pas les données locales.
